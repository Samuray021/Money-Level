# Проверка задач и релиза

Для задачи используются критерии её строки в атомарном бэклоге. Результаты команд и причины пропуска записываются в `PROGRESS.md`.

## Проверки рабочей ветки

```sh
pnpm install --frozen-lockfile
pnpm lint
pnpm format:check
pnpm typecheck
pnpm test
pnpm build
```

Для UI проверяется запуск сборки и затронутый сценарий в браузере. Проверки финансовой логики используют точные суммы из раздела 27 ТЗ.

## Критерии первого релиза

Раздел 29 ТЗ содержит полный список условий. Сквозные проверки охватывают запись и повтор команды, сверку отчёта с журналом, перезапуск без сети, резервное копирование и восстановление. На телефоне дополнительно проверяются скрытие сумм, фокус и настройка уменьшенного движения.

## Готовность эталонов ML-030

- TC-FIN-001–003. Сквозные команды проверяют баланс каждого счёта, сохранение общей суммы при переводе и пересчёт после мягкого удаления. Итоги отчётов сверены с селектором ML-046. Резерв в TC-FIN-001 и освобождение резерва в TC-FIN-004 сверены после ML-054.
- TC-FIN-005. Повтор после открытия базы возвращает прежнюю операцию и сохраняет одно событие. Сквозная проверка достижений зависит от ML-058–059 и ML-072–074.
- TC-FIN-006. Операции по обе стороны границы месяца сохраняют собственную дату после создания и редактирования. Месячный отчёт проверен в ML-046 по границе локальных дат.
- TC-FIN-007. ML-084 проверяет повторный импорт, баланс и резервы. Начисления будут сверены после модуля достижений.
- TC-FIN-010. Тесты finance-core проверяют точную сумму 0,10 + 0,20 и отклоняют дроби RUB с тремя знаками.

Для TC-FIN-004 ожидаемый остаток доступных средств составляет 55 700 ₽ по формуле из раздела 05.2 ТЗ и значениям примера.

## Сквозная проверка браузера

Для первого запуска установите Chromium командой `pnpm --filter @money-level/web exec playwright install chromium`. Команда `pnpm test:e2e` собирает приложение и проверяет сценарий ML-045 с выключенной сетью. Для системной сборки Chromium можно передать путь в `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.
