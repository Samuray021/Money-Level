# Проверка задач и релиза

Для задачи используются критерии её строки в атомарном бэклоге. Результаты команд и причины пропуска записываются в `PROGRESS.md`.

## Проверки рабочей ветки

```sh
pnpm install --frozen-lockfile
pnpm lint
pnpm format:check
pnpm typecheck
pnpm test
pnpm build
```

Для UI проверяется запуск сборки и затронутый сценарий в браузере. Проверки финансовой логики используют точные суммы из раздела 27 ТЗ.

## Критерии первого релиза

Раздел 29 ТЗ содержит полный список условий. Сквозные проверки охватывают запись и повтор команды, сверку отчёта с журналом, перезапуск без сети, резервное копирование и восстановление. На телефоне дополнительно проверяются скрытие сумм, фокус и настройка уменьшенного движения.

## Готовность эталонов ML-030

- TC-FIN-001–003. Сквозные команды проверяют баланс каждого счёта, сохранение общей суммы при переводе и пересчёт после мягкого удаления. Месячный отчёт проверен на том же журнале после перевода и повторного удаления. Резерв в TC-FIN-001 и освобождение резерва в TC-FIN-004 сверены после ML-054.
- TC-FIN-005. Повтор после открытия базы возвращает прежнюю операцию и сохраняет одно событие. Повтор операции и события также сохраняет один grant XP после ML-074.
- TC-FIN-006. Операции по обе стороны границы месяца сохраняют собственную дату после создания и редактирования. Месячный отчёт проверен в ML-046 по границе локальных дат.
- TC-FIN-007. ML-084 проверяет повторный импорт, баланс и резервы. ML-074 проверяет, что повторный импорт и обработка событий не начисляют XP повторно.
- TC-FIN-010. Тесты finance-core проверяют точную сумму 0,10 + 0,20 и отклоняют дроби RUB с тремя знаками.

Для TC-FIN-004 ожидаемый остаток доступных средств составляет 55 700 ₽ по формуле из раздела 05.2 ТЗ и значениям примера.

## Сквозная проверка браузера

Для первого запуска установите Chromium командой `pnpm --filter @money-level/web exec playwright install chromium`. Команда `pnpm test:e2e` собирает приложение и проверяет финансовый ввод, отчёты, приватные PNG, доступность, большой журнал, резервное копирование и офлайн-обновление. Для системной сборки Chromium можно передать путь в `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`.

## Проверка мобильного MVP ML-090

Оба браузерных прогона используют production-сборку на Debian 13 x86_64, AMD EPYC 9V74. Ширины 320, 390 и 768 CSS px проверены в эмуляции. Числа ниже относятся к этой среде.

| Среда                          | E2E | Баланс после навигации с 10 000 операций | p95 записи, 30 повторов |
| ------------------------------ | --- | ---------------------------------------- | ----------------------- |
| Chromium 156, профиль Pixel 7  | 6/6 | 426 мс                                   | 28 мс                   |
| WebKit 26.5, профиль iPhone 13 | 6/6 | 340 мс                                   | 52 мс                   |

- История показывает максимум 50 операций на странице. Смена страницы, возврат из карточки и фильтрация сохраняют порядок и итоговые суммы.
- p95 измерен от отправки формы до события `complete` транзакции IndexedDB. Время открытия баланса измерено от начала навигации до проверки отображения суммы.
- Проверены клавиатурный переход к содержимому, видимый фокус, системное уменьшение движения, скрытие сумм в формах и карточках. Axe-core 4.14.1 проверил 11 экранов на ширине 320 CSS px (нарушений по проверенным правилам WCAG A/AA не найдено).
- Для проверки офлайн-сценариев сервер закрывает соединения. Это сохраняет работу service worker в WebKit, где команда Playwright `setOffline` прерывает навигацию ещё до загрузки из кэша.
- Chromium запускается командой `pnpm test:e2e`. Для WebKit установите движок командой `pnpm --filter @money-level/web exec playwright install webkit` и запустите `PLAYWRIGHT_MOBILE_ENGINE=webkit pnpm test:e2e`.

### Проверка на реальных устройствах

| Устройство                                    | Статус       |
| --------------------------------------------- | ------------ |
| iPhone с Safari и запуском с домашнего экрана | Не проверено |
| Смартфон Android с Chrome и установленной PWA | Не проверено |

На каждом устройстве требуется записать модель, версии ОС и браузера. Проверяется установка PWA, повторное открытие в авиарежиме, сохранение операции, импорт JSON, сохранение PNG и системное меню, фокус и уменьшение движения. На эталонном смартфоне дополнительно измеряются баланс после загрузки и p95 сохранения при журнале из 10 000 операций. До получения результатов проверка ML-090 остаётся открытой.

## Проверки исправлений по аудиту

- AUD-001. `humor-settings.test.ts` проверяет 384 сочетания настроек. `humor.spec.ts` проверяет подписи и карточки разбора, настройки после перезапуска, тихую реакцию без воспроизведения, отключение компаньона и движения. `card-privacy.spec.ts` подтверждает прежнее скрытие данных.
- AUD-002. `domain-event.test.ts` проверяет все 16 типов контракта, включая 12 типов ТЗ, и исключает приватные поля. `domain-events.test.ts` воспроизводит реальные команды, атомарный откат порога, повтор команды, перезапуск, импорт, восстановление и единственную пасхалку из редкой реакции. `events.spec.ts` проходит открытие месячного и недельного отчёта и повторный запуск вкладки без дублей.
- AUD-003. `analytics-accounts.test.ts` проверяет фильтр счёта для обоих месяцев, архив, точные суммы, исключение перевода и opening из отчёта, пустой период и неизменность журнала. `analytics-accounts.spec.ts` проверяет переключение месяца и счёта, категории, таблицу и процент. Для незавершённого текущего месяца сохранено сравнение с полным предыдущим с явной подписью.
- AUD-004. `negative-account.spec.ts` проверяет сохранение расхода при нулевом счёте и положительном общем балансе, подсказки на главной и в списке, приватность и фильтр. Финансовые эталоны и проверки переводов подтверждают прежние точные суммы.
- AUD-005. `backup.test.ts` сверяет входные и новые записи, совпадения, конфликты, прогноз баланса и неизменность БД до подтверждения. Устаревший прогноз и структурный конфликт отклонены без записи. `backup.spec.ts` проверяет показ прогноза, скрытие суммы и повторный merge без дублей.
- AUD-006. `recovery.spec.ts` отдельно создаёт повреждённую старую базу и базу более новой версии. Тесты проверяют повтор открытия, отказ неправильной копии, корректный JSON, баланс после перезапуска и прежнюю запись с прежней версией в исходной БД. `backup.test.ts` блокирует восстановление в занятую базу.
- AUD-007. `goal-and-roast.spec.ts` проверяет уведомление о завершении цели при выключенном юморе, значок, сохранение общего баланса, доли и самую частую категорию, скрытие и пустой период. `domain-events.test.ts` проверяет повторное открытие и импорт квитанций. `card-privacy.spec.ts` и `backup.spec.ts` подтверждают приватность PNG и восстановление.
- AUD-008. `achievements.test.ts` проверяет выдачу 65 XP за семь дней записи, цель и экспорт, 10 XP при заполнении недели одним днём, сохранность финансовых итогов и повторный импорт. `xp.test.ts` проверяет вид, число очков и ключ награды. `pack.test.ts` и `evaluate.test.ts` проверяют лимиты схемы, безопасные ключи ассетов, отключение обычных и редких правил. `dto.test.ts` проверяет открытие старого профиля без отметки 18+. `humor-settings.test.ts` покрывает 768 комбинаций. `humor.spec.ts` и `mobile.spec.ts` проверяют сохранение и отзыв отметки в интерфейсе, доступность, клавиатуру и работу при выключенных эффектах.
