# Модель данных

## Общие контракты

| Поле          | Формат                                          |
| ------------- | ----------------------------------------------- |
| Идентификатор | UUID v4                                         |
| Дата операции | Календарная дата `YYYY-MM-DD`                   |
| Время записи  | Временная метка ISO 8601 в UTC                  |
| Валюта        | Код ISO 4217 из списка, поддерживаемого `Intl`  |
| Сумма         | Строка с целым числом минимальных единиц валюты |

Суммы `opening` и `adjustment` допускают знак. Суммы `income`, `expense` и `transfer` положительны. Валюта операции совпадает с базовой валютой и валютами её счетов.

## Журналы и события

- `Account` и `Category` сохраняют идентичность при архивации, чтобы старые записи оставались доступными в истории.
- `Transaction` хранит вид операции, сумму, валюту, счёт и локальную дату. Перевод хранит идентификатор счёта назначения. Доход и расход ссылаются на категорию своего типа.
- `GoalAllocation` хранит знаковую дельту резерва и ссылку на цель.
- `DomainEvent` связывается со своей исходной записью и публикуется после успешного сохранения операции.

Подробные поля и ограничения определены в разделах 22 и 23 ТЗ.

## Версии IndexedDB

Схема v1 включает счета, категории и финансовый журнал. Версии v2 и v3 добавили очередь outbox и результаты команд по ключу идемпотентности. Версия v4 проверяет существующие финансовые записи и фиксирует применение миграции в `appMigrations`. Ошибка валидации отменяет обновление схемы и сохраняет предыдущую базу.

Схема v5 добавляет настройки профиля, v6 добавляет цели и отдельный журнал резервов.

Схема v7 добавляет месячные бюджеты и отметки показанных порогов.

Схема v8 сохраняет локальный снимок восстановления перед заменой данных.

Схема v9 хранит результаты обработки событий по идентификатору потребителя и eventId.

Схема v10 хранит факт показа реакции, идентификаторы правила и сессии.

Схема v11 хранит достижения с уникальной парой вида и источника.

В AUD-002 у событий версии 1 есть собственные схемы payload. У существующих записей финансовых операций, создания цели и экспорта формат совместим с предыдущей сборкой. Порог бюджета фиксируется вместе с отметкой уведомления, прогресс цели вместе с выделением резерва, достижение вместе с выдачей XP. Сессия определяется UUID вкладки, отчёт фиксируется один раз для вида и начала периода в этой сессии. Пасхалка фиксируется при выборе допустимой редкой реакции. Подтверждение её события завершает обработку без повторной реакции. Схема хранилища остаётся v11.

При аварийном восстановлении приложение записывает проверенную копию в новую IndexedDB с префиксом `money-level-recovered-`. После успешной проверки восстановленного профиля локальный указатель выбирает новую базу при следующих запусках. Исходная база сохраняется. Перед попыткой открытия Dexie версия проверяется через IndexedDB, чтобы клиент не изменил схему более новой базы.

В AUD-008 в настройках профиля добавлен локальный флаг `adultHumorConfirmed`. Для предыдущих профилей и копий его значение по умолчанию — `false`. Для недельного достижения источник — понедельник календарной недели. Каждый день подтверждается сохранённой записью с совпадением даты операции и локальной даты её создания. Уже выданные достижения обычного формата сохраняются.
